# MusicPlayer-Mino

终端音乐播放器（Rust + ratatui + rodio）。

## 配置（`mino.toml`）

启动时按「程序当前目录 → 可执行文件所在目录」的顺序查找 `mino.toml`（仓库根目录已带一份模板）：

```toml
music_directory = 'E:\_music'   # 音乐目录
volume = 0.8                     # 启动时的初始音量，0.0 ~ 1.0
```

- 缺哪项就用哪项的默认值；删掉整个文件即全部用内置默认值。
- 写错不会让程序起不来：界面标题栏红字提示原因，同时音量会被夹紧到 `0.0 ~ 1.0`。
- 改完需**重启**生效；标题栏会显示当前实际加载的是哪个文件。
- 想加新配置项：往 `Config` 结构体加一个带默认值的字段（`impl Default` 里给值）即可，`mino.toml` 里就能覆盖。

## 快捷键

| 键          | 作用                                       |
| ----------- | ------------------------------------------ |
| 数字 + 回车 | 播放指定歌曲                               |
| `n` / `p`   | 下一首 / 上一首                            |
| 空格        | 暂停 / 继续                                |
| `m`         | 切换播放模式（顺序 → 列表循环 → 单曲循环） |
| `+` / `-`   | 音量加减（每步 0.05，范围 0.0 ~ 1.0）      |
| `r`         | 重连音频设备（耳机断电重连后没声音时用）   |
| `j` / `k`   | 移动列表光标（回车播放）                   |
| `↑` / `↓`   | 滚动列表窗口                               |
| `q`         | 退出                                       |

音量在播放中随时可调，状态行实时显示百分比（归零时标红）。

### 耳机重连后没声音？

蓝牙耳机没电断开、充上电再连回来时，系统里的输出端点其实已经换了一个新的，
而播放器线程还握着**打开时**那个旧端点 —— 声音全被送进了空气里，界面却照样显示「播放中」。

按 `r` 重新打开当前默认输出设备：旧句柄会被丢弃、重新开一个新的，
然后把当前曲目放回队列并从原进度续播（刷新前是暂停态就保持暂停）。
设备打开失败时会保留旧句柄，并在 stderr 打印原因。

设备一断，状态区那行提示会变成红字：

```
⚠ 音频设备已断开，按 r 重连（The requested device is no longer available）
```

重连成功后这行提示自动消失，恢复成平时的输入提示。

> 顺带一提：cpal 默认的错误回调是 `eprintln!`，会绕开 ratatui 直接往终端打字，
> 而 ratatui 只重画「变化过」的格子，那行字会永久糊在界面上。
> 所以这里用 `DeviceSinkBuilder::with_error_callback` 换掉了默认回调，
> 把错误投回命令通道、交给界面自己画（见 `audio::open_output`）。
